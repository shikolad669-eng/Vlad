# Automation — автоматизация бизнеса через Claude Code (ИИ)

Как ИИ (Claude Code) исполняет процессы этого бизнеса. Ключевая идея: **вика уже
живёт в namespace Claude Code**, markdown — источник правды; ИИ читает вику и
прогоняет переиспользуемые алгоритмы ([[phyto/phyto-vault/systems/lead-gen|lead-gen]],
[[phyto/phyto-vault/systems/promotion|promotion]]). Отработанный пример: снятие
всего каталога (780 SKU) из RSC-потока сайта + генерация лидов/алгоритмов.

## Модель: ИИ — движок, вика — данные

```
Источники (сайт, 2ГИС, Kaspi, Flip)  →  Claude Code (движок)  →  вика (markdown, правда)
                                             │
                       генерит черновики ────┴──── Влад ревьюит → публикует/отправляет
```

Данные и метод — LLM-независимы (переживают смену инструмента); Claude Code —
сменный движок над ними ([[../CLAUDE|карта неймспейса]]).

## ⚠ Главный принцип: ИИ готовит — человек публикует/отправляет

Жёсткий guardrail (безопасность + принципы namespace):

- **Наружу — только через апрув Влада.** Посты (Instagram/Threads), сообщения
  оптовикам, карточки маркетплейса, публичный контент — ИИ делает **черновик**,
  Влад проверяет и публикует/отправляет. **Никакого авто-постинга и авто-рассылки.**
- **Юр-рамка на каждом сгенерированном тексте:** «не является лекарственным
  средством», без обещаний лечения (см. [[phyto/phyto-vault/systems/promotion|promotion]] → Рамка).
- **Секреты** (Meta/Threads API, Kaspi-кабинет, доступы) — только в `~/vlad/secrets/`,
  не в git; в вике — указатели ([[phyto/phyto-vault/secrets-map|secrets-map]]).
- **Trust:** сгенерированное/снятое = `derived`, помечается; факты от Влада — отдельно.

## Что можно автоматизировать (безопасно, read/draft)

| Процесс | Что делает ИИ | Наружу? |
|---|---|---|
| **Каталог-рефреш** | Снимок цен/наличия с сайта (RSC-поток), диффы к `products.*` | нет (read) |
| **Контент-конвейер** | Черновики постов Threads/Instagram + карточек Kaspi/Flip из каталога, по контент-плану и юр-рамке | черновик → апрув |
| **Lead-gen** | Прогон [[phyto/phyto-vault/systems/lead-gen|lead-gen]] по городу/сегменту → пачка в [[phyto/phyto-vault/market/wholesale-leads|wholesale-leads]] + драфт скриптов касания | research да; отправка — Влад |
| **Прайсы** | Оптовый прайс под сегмент из `products.csv` + наценка (от Влада) | черновик |
| **Мониторинг** | Цены конкурентов/селлеров, отзывы, изменения ассортимента | нет (read) |
| **Ведение вики** | Актуализация `status`, `decisions`, `lessons` после прогонов | нет (внутр.) |

## Как технически (возможности Claude Code)

- **Скиллы / слэш-команды** под повторяющиеся прогоны: напр. `/catalog-refresh`,
  `/leadgen <город>`, `/content <тема>`, `/price <сегмент>`. (Оформить, когда процесс
  устоялся.)
- **Scheduled routines / cron** — расписание: еженедельный каталог-рефреш,
  контент-план на неделю, ежедневный черновик 1 поста.
- **Subagents** — параллельная разведка (лиды по нескольким городам сразу).
- **MCP-коннекторы** — по мере подключения доступов: Google Sheets (прайс/лиды),
  Meta/Threads API (очередь черновиков на апрув), Kaspi-кабинет, аналитика.
- **Память/вика** — источник правды; каждый прогон датируется, снимок устаревает.

## Роадмап (фазы)

- **Фаза 1 (сейчас, безопасно):** авто-снимок каталога; генерация черновиков
  контента / прайсов / лидов — всё в вику, публикация вручную. Доступы не нужны.
- **Фаза 2:** MCP к Google Sheets (прайсы/лиды) + scheduled routine на
  каталог-рефреш и недельный контент-план. Нужны: доступы в `secrets/`.
- **Фаза 3:** Threads/Instagram API — черновики в очередь на апрув; мониторинг
  отзывов/цен; дашборд метрик по каналам.
