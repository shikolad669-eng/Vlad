# ideas/ — future improvements & open architecture questions

Where **ideas, concepts, and ways to improve the meta level** are held —
forward-looking proposals and open questions about the namespace and how it all
integrates, **distinct from settled decisions**.

## What goes here vs the siblings

| Folder / file | Holds | Maturity |
|---|---|---|
| **`ideas/`** (this) | proposals, directions, open questions at the vault / whole-system level | candidate — not settled |
| `decisions/` | settled ADRs — a verdict + why + context + status | graduated |

## Graduation

An idea is not meant to live here forever. When it ripens it **graduates**:
into `decisions/` (a settled ADR), into method canon as a real demand, or it's
dropped (record why). An idea doc may carry a decided core with open questions —
the decided parts graduate question by question; the doc stays until the open
set is closed.

## Conventions

- Filename: `YYYY-MM-DD-<slug>.md` for dated proposals; plain `<slug>.md` for
  standing threads.
- Frontmatter: `type: idea`, `status: active | graduated | dropped`, `tags`,
  `related`. Mark which parts are decided vs open in the intro.
- Keep `HOME.md` → "Ideas" section pointing at the live ones.
